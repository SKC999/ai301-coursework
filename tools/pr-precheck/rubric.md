# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every file and hunk in the diff read against the plan's scope, files list, approach and not-in-scope line, plus any deviation note in the plan or the description. Then every deliverable the plan names read against the diff. | Pass if every hunk does work the plan or a deviation note names and every planned deliverable is in the diff or is recorded as deferred in the plan's note. Fail if any hunk changes a file or behavior the plan does not name (a new flag or setting, a rename pass, a rewrite of a neighboring function, a file outside the plan's files list) with no deviation note. Fail if a planned deliverable such as a docs update or a second fix is missing with no note. Tests for the planned fix and imports it needs count as planned work. | required |
| description-faithful | Each factual claim in the PR description read against the diff. Look hardest at fidelity claims such as "exactly as planned", "implements the plan in full", "no changes beyond the plan", "docs updated" or "no functional changes outside X". | Pass if every claim about what the PR changes is visible in the diff and the description does not deny any change the diff makes. Fail if the description claims work the diff does not contain or claims fidelity or a narrow scope that the diff contradicts. | required |
| repro-before-after | The test evidence read against the plan's test plan and repro evidence. Find the failing case the repro isolated and the expected-after the plan states. | Pass if the evidence re-runs the plan's own failing repro on the changed code path and shows observable before and after output, and the after matches the plan's expected-after. When the test plan names more than one failure case each one is shown. Fail if the evidence is only a claim ("tested locally", "works now", "verified on my machine"), if it runs only a control or a path the fix does not change, or if a failure case the test plan names is never re-run. | required |
| repo-checks-run | The test evidence read against the test suite or checks named in the plan's test plan and the repo facts or contribution docs (cargo test, pytest, make test-unit, yarn test, lint and type checks). | Pass if the evidence states that the named suite or checks were run on the branch and gives their outcome, or reports a failing check honestly with its reason. Fail if the suite or checks the plan or repo names were never run or no outcome is stated. | required |
| no-debris | Every hunk of the diff read line by line for leftovers that are not part of the fix. | Pass if every added or changed line serves the fix, its tests or a needed import, and short comments explaining the fix are fine. Fail if the diff carries any debug print or log left from debugging (including a commented-out one), a commented-out block or old attempt, a dead function or helper nothing calls, a stray TODO, or formatting, re-indent or import reshuffle churn on lines the fix does not need. | required |
| template-asks-met | The repo facts block's PR template and contribution asks (live mode: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`) read against the title, description and diff. | Pass if every ask the repo states for a PR is honored. Named template sections hold real content, a required issue link line such as "closes #N" or "fixes #N" is present, a required checklist is answered, and a required changelog or whatsnew entry appears in the diff. Pass when the repo states no PR asks. Asks that a PR package cannot show (a signed CLA, a vouch flow, CI status after opening) do not count. Fail if any stated ask is visibly skipped. | required |
| ai-disclosure | The repo's stated AI policy in the repo facts block (live mode: `docs/CONTRIBUTING.md` and the course rule that every PR discloses AI use) read against the description. Treat every package as AI-assisted work. | Pass if the repo states no AI disclosure requirement, or if the description discloses AI use the way the policy asks. Fail if the policy requires disclosing AI use and the description has no disclosure. | required |
| commit-messages | The commit list. | Pass if each commit message says what it changes. Fail if commits read like "wip", "fix" or "misc cleanups". | preferred |

## Verdict rule

The verdict is accept only when every required check grades pass. One required fail makes the verdict reject. An unclear grade on a required check counts as a fail because a pull request we cannot verify from the package is not ready to submit. Grade unclear only when the package truly holds no evidence for a check. When evidence is present the grader decides pass or fail. The preferred check never changes the verdict and is reported in the summary only.

An honest shortfall does not fail any check. When the plan's note defers part of the work and the description says so too, the missing part is recorded and the pull request can still be accepted.
